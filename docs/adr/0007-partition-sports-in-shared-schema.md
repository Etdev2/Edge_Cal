# Partition sports in the shared schema

The calculator supports multiple sports (NBA today, NFL added 2026-09) using one set of core tables. Each league is partitioned by a `sport` column (`'nba' | 'nfl'`) on `teams`, `players`, `games`, `player_game_stats`, and `analysis_snapshots`; every query is sport-scoped so evidence windows never mix leagues. League-specific box-score fields live as nullable-free integer columns on `player_game_stats` (NBA fields are 0 for NFL rows and vice versa) rather than in separate per-sport tables, because the evidence pipeline (DNP exclusion, low-activity flag, push settlement, the 7 windows, Wilson intervals) is sport-agnostic and a single row shape keeps that guarantee auditable in one place. Markets are resolved from a sport-scoped registry (`getMarketsBySport`), and `POST /api/analysis` rejects a player that does not belong to the requested sport with an explicit error. A future third sport (e.g., soccer) may require a different market model (three-way result markets) and would be evaluated for its own tables at that time; the current partitioning keeps that option open without blocking the NBA/NFL extension.
